# Nova UI/UX Skill Audit — 2026-09-27

## Result

The repository has been reviewed against its current tree and against the five requested external repositories.

### Current Nova repository state

The GitHub repository currently contains the Nova skill instructions, plugin metadata, README prompts, production-readiness references, design philosophy, PRD/TRD design selection, external reference matrix, and the Expo dynamic-notification reference.

It is **not yet a byte-for-byte mirror of the earlier 682-file / ~21.7 MB package**. The current GitHub tree is much smaller. Therefore, any README wording that implies the full historical data catalogs are physically present must be treated as package claims rather than verified repository contents until the full package is synchronized.

## Findings

### P0 — distribution completeness
The earlier package contained a large canonical data/script/template set that is not represented in the current GitHub tree. The repository should not be described as a complete mirror until those assets are synchronized.

### P1 — external-reference completeness
The five repositories were previously summarized at a high level. This audit adds a detailed coverage record in `docs/EXTERNAL-REFERENCE-COVERAGE.md` so their reusable concepts are not lost.

### P1 — runtime dependency guidance
Advanced visual features must not be treated as dependency-free. R3F/Three/shader systems require version compatibility checks, and WebGL effects require fallbacks.

### P1 — visual effects and accessibility
Liquid glass, shaders, 3D and scroll cinematics require explicit reduced-motion, static/fallback, contrast, focus and performance treatment.

### P2 — source attribution
Nova references external repositories as sources/pattern libraries. It does not claim their code or assets as Nova-owned. Direct reuse must follow each upstream license and asset-specific rights.

### P2 — README capability claims
The README lists searchable catalog counts from the earlier package. Those counts should be retained only as package metadata if the complete package is restored, otherwise they should be changed to `reference package` counts and clearly marked as not currently synchronized into GitHub.

## Five-repository coverage

- React Three Fiber: architecture, Canvas, events, hooks, objects, TypeScript, testing, pitfalls and scaling performance.
- Liquid Glass JS: shapes, refraction, nested glass, parameters, blur, tint, sampling, responsive behavior and browser requirements.
- Scroll World: interview workflow, art direction, camera grammar, scene chain, frame-identical seams, mobile 9:16, budget, rendering pipeline, scrub engine and QA.
- Liquid Logo: shader-driven identity treatment, canonical-logo preservation, React/Next integration and progressive enhancement.
- ShaderGradient: renderer separation, 3D gradient controls, camera/light/material settings, query presets, lazy loading, pixel density and React/Vue compatibility.

## Required acceptance criteria

A future complete release should not be marked complete until:

- [ ] Canonical package data/scripts/templates are present in GitHub.
- [ ] README counts match files actually present.
- [ ] External reference coverage is linked from SKILL.md.
- [ ] PRD/TRD design selection is part of the default workflow.
- [ ] Advanced visual effects have fallbacks and reduced-motion behavior.
- [ ] Dependency compatibility is documented for the target stack.
- [ ] Licenses/attribution are preserved for direct third-party reuse.
- [ ] Validation scripts/tests are runnable from the repository.
- [ ] A release archive is reproducible from the repository.
